# TalkType 产品设计方案

## Context

TalkType 是一款**语音输入法**，定位与讯飞输入法、搜狗语音输入等对齐，但核心差异在于：100% 本地处理（隐私优先）+ 三级文本处理能力（原始识别 → 语义修复 → 语气转换）。这是学习项目，目标是完整走通产品设计与实现。

---

## 一、产品能力分层

```
┌──────────────────────────────────────────────────────┐
│  可选：语气转换（正式 / 专业 / 委婉 / 暧昧 等）        │  本地 LLM
│  ↑ 在基础文本基础上转换                               │
│  基础修正（自动）：去语气助词 + 标点修正 + 重复词去重  │  规则引擎
│  ↑ 在原始识别基础上                                   │
│  原始识别：Whisper 语音转文字                         │  whisper.cpp
└──────────────────────────────────────────────────────┘
```

### 第一层：基础修正（自动执行，规则引擎）
每次识别后自动完成，无需用户操作：
- 去语气助词：过滤"嗯""那个""就是""然后嘛""对吧""你懂我意思吗"等
- 标点补全：句尾自动加句号，疑问句加问号，列举加逗号
- 重复词去重："这个这个" → "这个"
- 输出：**基础文本**（干净、可直接使用的文字）

### 第二层：语气转换（可选，本地 LLM）
以基础文本为输入，转换为用户选定的风格：
- **正式**：适合邮件、公文、报告
- **专业**：适合技术文档、学术写作
- **委婉**：适合拒绝、建议、反馈场景
- **暧昧**：适合社交聊天（保留情感模糊性）
- 后期支持用户自定义风格 Prompt
- 输出：**风格文本**

## 二、核心交互流程

### 场景 A：未启用语气转换（默认）
```
按住热键 → 录音 → 松开 → Whisper 识别 → 规则引擎基础修正 → 直接插入文字
```
无浮窗，完全静默插入，体验与系统输入法一致。

### 场景 B：已启用语气转换
```
按住热键 → 录音 → 松开 → Whisper 识别
                                │
                    ┌───────────┴───────────┐
                    ▼                       ▼
             规则引擎基础修正          基础文本 → LLM 语气转换
             （<0.5秒）                （~1-3秒）
                    │                       │
                    └───────────┬───────────┘
                                ▼
              ┌─────────────────────────────────┐
              │           浮窗弹出              │
              │                                 │
              │  [基础文本]  去语气词后的干净文字 │  ← 点击或按 1
              │  [风格文本]  转换后（加载动画）   │  ← 点击或按 2
              │                                 │
              │  ESC → 取消；不操作5秒 → 自动    │
              │  插入基础文本                    │
              └─────────────────────────────────┘
```

**浮窗设计要点：**
- 基础文本立即显示，风格文本异步加载（显示转圈动画）
- LLM 未完成时用户可直接选基础文本，无需等待
- 超时 5 秒未选择：自动插入基础文本
- 键盘：`1` = 基础文本，`2` = 风格文本，`ESC` = 取消
- 浮窗位置：优先跟随光标，无法获取时固定在屏幕底部中央

**示例：**
```
说话：「然后就是，我觉得吧，这个方案可能不太行，你懂我意思吗」

基础文本：「我觉得这个方案可能不太行。」
风格文本（正式）：「我认为该方案存在明显不足，建议重新评估。」
风格文本（委婉）：「这个方案或许还有一些优化空间。」
```

## 三、LLM 技术方案

### 本地 LLM（默认）

| 模型 | 大小 | 中文质量 | 适用场景 |
|---|---|---|---|
| Qwen2.5-0.5B（GGUF Q4）| ~400MB | ★★★ | 低端设备，快速 |
| Qwen2.5-1.5B（GGUF Q4）| ~1GB | ★★★★ | 主力推荐 |
| Qwen2.5-3B（GGUF Q4）| ~2GB | ★★★★★ | 高端设备 |

**为什么选 Qwen 系列：** 中文能力远超同尺寸英文模型，GGUF 格式可直接用 llama.cpp 推理，MIT 许可证。

**推理引擎：** llama.cpp（同样支持 CoreML/Metal 加速）

### 外部 LLM（用户自定义接入，后期扩展）

用户可在设置中填入自己的 API Key（OpenAI / Claude / DeepSeek 等），App 将 prompt + 识别文本发送到用户指定的接口。**App 自身不托管任何 API Key，不经过 TalkType 服务器。**

## 四、Whisper 模型策略

用户手动选择，App 不自动切换。

| 模型 | 参数量 | 中文质量 | 推荐设备 |
|---|---|---|---|
| whisper-tiny | 39M | ★★★ | 所有设备 |
| whisper-base | 74M | ★★★★ | 4GB RAM+ |
| whisper-small | 244M | ★★★★★ | 8GB RAM+（主力推荐）|
| whisper-medium | 769M | ★★★★★+ | 16GB RAM+ |
| whisper-large-v3 | 1.5B | 最高 | 高端设备 |

## 五、模型分发架构

| 类型 | 来源 | 分发方式 |
|---|---|---|
| Whisper 开源模型 | Hugging Face（ggerganov/whisper.cpp）| App 内下载，HF CDN + hf-mirror.com 备用 |
| LLM 开源模型 | Hugging Face（Qwen GGUF）| App 内下载，同上 |
| 付费领域微调模型 | 自建仓库 | License Key 解锁 → 预签名 URL 下载 |

**存储路径：** `~/Library/Application Support/TalkType/models/`
**模型管理 UI：** 文件大小、内存需求、质量评级、下载状态/进度；用户手动下载，手动切换。

## 六、系统兼容性检测

```
检测项                      处理
────────────────────────────────────────────────────
macOS 版本 < 12.0           警告提示，建议升级
Apple Silicon / Intel       自动选 CoreML/Metal 或 CPU 后端
内存 < 模型需求              模型列表标注"内存不足"（不阻止下载）
磁盘 < 模型大小×2           下载前提示
麦克风权限未授权             首次启动引导，未授权则禁用录音
辅助功能权限                可选，未授权自动降级为 Pasteboard 插入
```

首次运行新模型时做基准测试：若推理 >5秒/10秒音频，提示用户换小模型（不强制）。

## 七、技术栈

| 层 | 技术 |
|---|---|

## 八、UX 设计

**核心交互：Push-to-Talk**
```
按住热键 → 录音 → 松开 → Whisper 识别 → 浮窗三选一 → 插入文字
```

**状态指示（菜单栏图标，5态）：**
待机 / 录音中（脉冲）/ 识别中（旋转）/ 浮窗展示中 / 错误（红色）

**语气风格切换：** 菜单栏图标右键菜单 → 选择当前语气风格（正式/专业/委婉/暧昧），随时切换，下次识别即生效。

**Onboarding（4步）：**
1. 授权麦克风（强调"音频仅本地处理"）
2. 选择 Whisper 模型并下载
3. 选择是否启用 LLM（下载 Qwen 模型，可跳过）
4. 设置全局热键

## 九、开发顺序

```
Week 1-2：ASR 核心
  - whisper.cpp Swift 集成 + 音频采集
  - 基础规则引擎（去语气助词、标点补全）

Week 3-4：macOS 应用骨架
  - 菜单栏 App + 全局热键
  - 浮窗 UI（三选一交互）
  - 文字插入（Pasteboard）

Week 5-6：LLM 集成
  - llama.cpp Swift 集成
  - 语义修复 Prompt 设计与测试
  - 语气转换 Prompt 设计与测试
  - 并发处理（ASR 完成后同时触发两个 LLM 任务）

Week 7-8：模型管理 + 产品化
  - 模型下载管理器（HF CDN）
  - 兼容性检测
  - 偏好设置 UI（热键 / 模型 / 语气风格默认值）
  - Onboarding 流程
```

## 十、关键技术风险

| 风险 | 应对 |
|---|---|
| 本地 LLM 在低端设备延迟高（>5秒）| 低端设备跳过 LLM，浮窗只展示基础版本；或将 LLM 设为可选功能 |
| 浮窗位置计算（跨 App 光标定位）| 基础方案：固定在屏幕底部；进阶：用 Accessibility API 获取光标坐标 |
| llama.cpp + whisper.cpp 同时运行内存压力 | 串行而非并行（ASR 完成释放后再启动 LLM）；或共享内存池 |
| Prompt 质量不稳定（LLM 输出格式不可控）| 严格的 Output Format 约束 + 失败时 fallback 到基础文本 |
| HF 模型下载在国内慢 | 优先 hf-mirror.com 镜像，用户可自定义下载源 |
